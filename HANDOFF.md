# Hand-over

Where Boardwright stands and how to continue, for any Claude (or person) picking it up. Update it at the end of each working session.

**State (2026-11-24): version 0.7.0, on `main`.** Pushed up to `0e38465`; local commit `290a03c` (Freerouting rounds on big boards) and the files from this hand-over are not pushed yet.

## What exists
- **Claude Code plugin** (`plugin/`): skills `pcb-*`, hooks (`plugin/scripts/edit_hooks.py`: edit lock, history, guards), gate scripts, the MCP server `plugin/scripts/bw_mcp.py` (15 tools).
- **Routing engine** (`plugin/scripts/engine.py`, `engine_kicad.py`): KiCadRoutingTools 0.24.1 (strict) and Freerouting 2.6.0 (pinned by checksum), installed by `plugin/scripts/setup_engine.ps1` / `.sh`. Three variants run side by side and the best DRC-clean result is kept. Results and what was tried: `docs/benchmark-engine.md`; congestion-aware routing notes: `docs/research/pathfinder-plan.md`; research report: `reports/Routing engine improvement plan.md` in the example project folder.
- **KiCad add-on** (`kicad-addon/`): the chat window (`bw_chat.py`, `bw_core.py`, `bw_theme.py`, `bw_dock.py`), built into `kicad-addon/dist/boardwright-kicad.zip` by `build.py`.
- **User guide**: `docs/Boardwright-User-Guide.pdf` (source `docs/guide/user-guide.html`; screenshots by `tools/guide/capture_window.py`).

## Routing accuracy: task list (from `reports/Routing ideas from KiCad community.md` in the example project)
Done in this round: plane layers are detected and kept free of tracks in both routers, with an audit that drops any net whose new copper runs on another net's plane or is smaller than its net class (KiCad's DRC checks neither); a "Net class sizes" note in the gates; Freerouting best-of-N seeds when free memory allows (forced 3 seeds: cm5 unchanged, royalblue 44 -> 37 open, within its run-to-run spread, so inconclusive).
Plane-protection benchmark (`tools/bench/results/engine-planes.json`, open connections after): kit-dev 181 (was 2 when Freerouting could cut the planes), cm5 35, royalblue 72, video 196 (was about 280), jetson 1835. Diagnosed on kit-dev and fixed (2026-11-25):
- the plane repair laid GND/+3.3V at the board default (0.2 mm, 0.6 mm vias) instead of their class (0.4 mm, 0.8/0.4 mm): `engine_kicad rules` now returns `pour_classes` and `planes_stage` passes them (`--track-width`, `--min-track-width`, `--via-size`, `--via-drill`), plus `--layers/--layer-costs` so it lays no tracks on plane layers;
- the plane repair (and KiCadRoutingTools' rip-up) moves other nets' tracks out of the way; only the routed nets were merged, so new vias landed on the old positions. `engine_kicad moved` lists those nets and `evaluate` merges and checks them with the routed ones;
- KiCadRoutingTools and Freerouting route over board text on copper layers (4 nets per run on kit-dev): `engine_kicad textguard` adds keep-outs over that text in the routers' working copies only (merge takes tracks and vias only);
- the plane repair necks a tap down to a fine-pitch pad's width (0.3 mm): `engine_kicad trim` cuts such single-segment taps (that pad stays open) instead of dropping the whole pour net. Owner's decision (2026-11-25): a track may narrow below its net class at a pad of its own net, only as far as needed (no narrower than the smaller of the class width and the pad's short side, at most 2 mm long); `neck_down` in `engine_kicad.py` audit.
Next, in order:
1. **Bench harness:** `--repeat N` (done) and paired per-board results, so a change is judged against run-to-run spread (cm5 has varied 10-24 open, royalblue 28-45).
2. **KiCadRoutingTools 0.24.2** (downloaded to `%LOCALAPPDATA%\Boardwright\engine\krt-0.24.2` for testing, switch `BOARDWRIGHT_KRT_DIR`): on kit-dev it gave the same result as 0.24.1 (183 open both). Not adopted; A/B on the other boards only if time allows. Note: its Rust router still reports 0.24.1, so its `rust_router/Cargo.toml` must say 0.24.1.
2a. **Round 7 (2026-11-25), done:** fast nets also by impedance-named class and pair-member names; differential pairs routed coupled by KiCadRoutingTools' pair router with `--allow-fast` (whole pairs only, never to the single-track routers); no vias in pads unless the design has them or `boardwright.json` `"engine": {"via_in_pad": true}`; nets finished before the run and nets the engine must not route are locked in the routers' copies and never moved; the audit judges only new copper. Results in `docs/benchmark-engine.md`, round 7. Rejected: taking pairs the pair router calls "electrically short" as two tracks (its floor was 100 mm on jetson). Next for pairs on jetson (fan-out tried 2026-11-25, not added): `bga_fanout.py` on J1 (the 699-pin module connector) escaped all 100 pair pins in 5 min (`auto`, 4 new DRC errors: shorts onto C22/C19 GND pads) or 89 (`dogbone`, 24 errors), but the pair router then routed 0 pairs in 16-22 min. Root cause: jetson's high-speed classes set no sizes, so they fall back to its Default class, whose pair width and gap are placeholders (5 mm); the real sizes are custom rules in its `.kicad_dru` (0.125-0.19 mm, gaps 0.10-0.18 mm). The pair router (its "electrically short" floor came out at 100 mm), the fan-out (0.3 mm tracks) and the engine's size audit all read the 5 mm. Needed, in order: sizes read from the rules file (KiCad's Python has no rule evaluation; KiCadRoutingTools' `design_rules.py` has `draw_size`), the pair router run per interface with that width and gap, the fan-out with those widths, then the pair router after it. Scripts used: `fanout_try.py`, `pair_group.py` (session scratchpad, not kept); stickhub's USB pairs are named `/U1D+`, so only a `high_speed.pairs` entry in `boardwright.json` marks them.

2e. **Round 10 (2026-11-26), done:** Freerouting runs without its fan-out pass (video 217 -> 164 and 494 -> 324 open in same-load pairs, neutral on the others). jetson stays near 1480 open: Freerouting manages about one pass in 15 minutes there and completes no net, so the next gain on jetson needs a faster router for its size, not settings.
2d. **Round 9 (2026-11-26), done:** pair groups split into runs of at most 12 pairs (`pair_chunks`), and the big pour nets go to the plane repair before the pairs (after 150 pair nets it did not finish in 60 minutes). jetson `--allow-fast`: 1639 -> 1482 open, 36 -> 151 pair nets, 0 new DRC errors. Rejected: runs of 8 (fewer pairs, slower); plane repair after the pairs with fewer A* iterations or no recheck (still not done in 30 minutes). Next: the inner-layer second run for pairs whose rule sizes differ by layer (see 2c).
2c. **Round 8 (2026-11-25), done:** sizes are read from the project's rules file per layer (`plugin/scripts/engine_rules.py`, run with KiCadRoutingTools' Python); the audit and trim use them; pairs are routed per size group at their rule width and gap, on the layers where those sizes hold. jetson's pairs now route (see `docs/benchmark-engine.md`, round 8). Rejected: fan-out before the pair router (3 pairs against 8); one size on every layer (wrong width on the outer layers). Next: jetson's 85 ohm group (42 pairs) runs out of 15 minutes and keeps nothing (the pair router does not read the stop file): split a big group into smaller runs, or give it a longer limit on big boards. Also: pairs whose rule sizes differ inside could get a second run on the inner layers from the escapes of the first, if the pair router learns to start from stubs ("endpoint-resolution-failure" after a fan-out).
2b. **The leftovers pass (krt2) adds almost nothing** (0-3 nets on kit-dev, 0 on cm5 and royalblue): it rips up routed nets, cannot route them back, and the engine then drops them and the nets that took their space. Tried 2026-11-25, none better (kit-dev, KiCadRoutingTools only, 15 min per stage): `--max-ripup 0` for krt2 (118 open against 46-62; it still moved 7 nets), `repair_planes --rip-blocker-nets` (timed out, 179), accepting a moved net left slightly more open when the stage closes 3x more (never triggered, 62 both; removed), a 0.05 mm grid for krt2 on royalblue (77 and 82 against 82 and 79). Switches for such tests: `BOARDWRIGHT_KRT_ARGS`, `BOARDWRIGHT_KRT2_ARGS`, `BOARDWRIGHT_PLANES_ARGS`, `BOARDWRIGHT_FREEROUTING_ARGS`. What is left on the boards now: cm5's DPHY differential pairs (need pair routing, KiCadRoutingTools has it), royalblue's fine-pitch U1 (Freerouting drops 8 nets there for DRC errors).
3. **jetson's custom rules:** its `.kicad_dru` (for example `hs_zone_clearance`) cannot go into Freerouting's DSN, which is the leading suspect for Freerouting completing almost nothing there. Tighten the DSN clearances from the rules file, or route those nets with KiCadRoutingTools only.
4. **Claude placement plans:** KiCadRoutingTools reads `groups.json` (its native plan format) and places with `py_placer/place_simple.py`; Claude writes the plan, a saved plan replays without Claude. Needs an "unplaced" bench mode (strip placement as well as copper). Ignore any via, track or clearance numbers in a plan: they could loosen a rule.
5. **Topological bus routing** (`awx/route_bus.py`, arXiv 2610.35601): only for boards with a bus of about 8+ nets between ball arrays; no demo board has one. It can lay copper below the requested sizes, so it may run only behind the size audit, and only on approved BGA test boards (a download).
6. **Congestion-aware routing in the Rust core:** see `docs/research/pathfinder-plan.md`.
